Proceso de entrada y validación al sistema transaccional

Flujo con autenticación en dos pasos: credenciales (login y contraseña) y, a continuación, página de verificación del código OTP enviado al teléfono móvil.

1. Diagrama de flujo

flowchart TD
    A([Inicio]) --> B[Usuario abre página de login]
    B --> C[Ingresa usuario/correo y contraseña]
    C --> D{¿Campos completos?}
    D -->|No| E[Error: campos requeridos]
    E --> C
    D -->|Sí| F[Enviar credenciales por HTTPS]
    F --> G{¿Usuario y contraseña válidos?}
    G -->|No| H[Intento fallido / mensaje genérico]
    H --> C
    G -->|Sí| N[Generar OTP de un solo uso]
    N --> O[Guardar OTP hasheado + expiración]
    O --> P[Enviar OTP por SMS al móvil]
    P --> Q[Página: escriba el código del teléfono]
    Q --> R[Usuario ingresa OTP]
    R --> U{¿OTP correcto y vigente?}
    U -->|No| W[Reintento / reenvío / bloqueo]
    W --> Q
    U -->|Sí| AA[Crear sesión segura]
    AA --> AC[Acceso al sistema transaccional]
    AC --> AD([Fin - acceso concedido])

2. Diagrama de secuencia

sequenceDiagram
    autonumber
    actor U as Usuario
    participant UI as Página Web
    participant API as API Autenticación
    participant DB as Base de datos
    participant SMS as Servicio SMS

    U->>UI: Abre /login
    U->>UI: Envía usuario + contraseña
    UI->>API: POST /auth/login HTTPS
    API->>DB: Verificar hash de contraseña
    alt Credenciales inválidas
        API-->>UI: 401
        UI-->>U: Error genérico
    else Credenciales válidas
        API->>DB: Guardar reto OTP
        API->>SMS: Enviar código al móvil
        SMS-->>U: SMS con OTP
        API-->>UI: Requiere OTP
        UI-->>U: Página de código SMS
        U->>UI: Ingresa OTP
        UI->>API: POST /auth/verify-otp
        API->>DB: Validar OTP
        API-->>UI: Sesión OK
        UI-->>U: Sistema transaccional
    end
